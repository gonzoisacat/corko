# Contributing

Corko takes **suggestions, not code**. Open an issue; do not open a
pull request.

## Why

The maintainer is the sole copyright holder, which is what keeps every
future option open for the project (its license, a hosted version, a
change of direction). Merging outside code would end that unless every
contributor first signed an agreement, and a small project is better
served by skipping the paperwork. So no outside code is merged, ever,
and an automation closes pull requests on arrival with a note.

There is a second, practical reason. This public repo is a snapshot:
each release is one commit copied out of a private working repo. A
change merged here would be overwritten by the next release.

## What helps

- **A bug**: what you did, what you expected, what happened, the
  browser, and the version you are running (`npm pkg get version` in
  your checkout, or the changelog entry your instance was deployed
  from).
- **An idea**: the problem you are trying to solve, before the feature
  you have in mind. The product is a beat board for documentary editing
  and is deliberately not a general whiteboard.
- **A fix you have already made** in your own copy: describe it in an
  issue, with the diff if you like. It will be considered and, if
  taken, implemented in the working repo and credited in the changelog.

## Security

Use GitHub's private vulnerability reporting on this repo's Security
tab rather than a public issue.
